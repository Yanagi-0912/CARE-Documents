# CARE 共用專案事實

最後核對：2026-10-02

## 基本資料

- 專案名稱：CARE - Clinical Assistance & Resource Engine
- 專案定位：以 LINE 為主要入口的高齡友善健康與醫療資訊智慧助理。
- 主要使用者：高齡者、家庭照顧者、不熟悉複雜數位服務者，以及有台語或多語互動需求者。
- 核心目標：降低取得、理解與管理健康資訊的門檻，並以家庭帳號支援日常照護。
- 醫療邊界：提供健康資訊、紀錄與照護輔助，不進行診斷、不取代醫師或藥師。
- 開發文件列名：游承諺、王洪賢、張宸翊、蘇奕勳、蕭丞佑。

## 問題與價值

CARE 聚焦三項相互關聯的問題：

1. 健康與醫療資訊來源繁雜，使用者難以判斷可信度。
2. 高齡者可能受文字閱讀、複雜介面及華語語音服務限制。
3. 健康紀錄、用藥、就醫與家人照護分散於不同工具，使用成本高。

CARE 使用熟悉的 LINE 對話作為入口，結合可信資訊檢索、語音與多媒體處理、健康紀錄、用藥提醒、醫療資源查詢及家庭權限，讓使用者可在同一服務中完成日常健康資訊任務。

## 已確認技術

- 後端：Python、FastAPI、LangGraph
- 前端：React、TypeScript、LIFF
- 介面：LINE Messaging API
- AI：Gemini 系列模型、RAG、查核與回覆可靠性流程
- 檢索與資料：PostgreSQL + pgvector、MongoDB、Redis
- 語音：Gemini STT、Taigi AI Labs STT/TTS
- 多媒體：OCR、音訊、影片及文件文字擷取流程
- 部署：Docker、Kubernetes、Helm、Kong/Ingress、n8n
- 主要資料來源：衛生福利部、疾病管制署、食藥署、官方衛教資料、醫療資源公開資料等；實際納入來源由白名單與資料管線控制。

## 台語互動流程

```text
台語語音輸入
  -> 台語 STT 與華語 STT 候選處理
  -> 語言與意圖判斷
  -> RAG／系統工具／安全規則
  -> 產生文字答案
  -> 台語文字改寫
  -> Taigi AI Labs TTS
  -> LINE 語音回覆
```

目前程式已串接 Taigi AI Labs API。既有 GCP Pod 基準測試顯示，10 至 150 字測項均無失敗或逾時；這是合成語音與固定測句的工程基準，不等同真實高齡使用者場域成效。STT 的平均字元錯誤率依長度約為 0% 至 13.7%，台語異體字也會被計為錯誤；TTS 完整 WAV 回應中位數依長度約為 1.55 至 7.86 秒。

## 可靠性與安全原則

- 回覆附可追溯來源，資料不足時不自行補造答案。
- 健康傳言可進行主張辨識、檢索與證據式說明。
- 藥袋 OCR 結果須由使用者核對後才進入後續流程。
- 用藥風險提示不代表未提示即安全，並應引導諮詢醫師或藥師。
- 跨使用者資料依 GENERAL、SENSITIVE、PRIVATE、PERSONAL 分類及角色動作控管。
- 定位僅在使用者授權與走失分享有效期間內提供給合格家屬。
- 不宣稱通過醫療器材認證或具有疾病診斷效能。
