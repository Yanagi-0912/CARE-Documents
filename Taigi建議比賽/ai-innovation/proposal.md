# CARE：高齡健康照護場景的可信多模態 AI 助理

> 正式版提案內容以 2 頁 A4 為原則。

## 一、提案主題

CARE 以 LINE 為介面，建立能理解文字、語音、圖片與文件的健康照護 AI 助理。核心創新不是一般聊天介面，而是把可信檢索、多模態前處理、台語語音、工具執行、安全規則與家庭權限整合為一條可驗證管線。

## 二、問題與應用情境

高齡者取得健康資訊時，可能同時遇到資訊真假、閱讀負擔、台語溝通與複雜操作問題。家庭照顧者則需要協助紀錄與提醒，但不應因此取得所有私人資料。CARE 讓使用者直接在 LINE 提問、傳語音或拍藥袋，取得附來源的資訊及下一步操作；敏感資料依角色、分類與動作限制。

## 三、AI 架構

### RAG Pipeline

```text
User Query
 -> 意圖與查詢重寫
 -> 向量／文字混合檢索
 -> 可信來源過濾
 -> Cohere Rerank
 -> Context Construction
 -> Gemini 回覆生成
 -> 引用與資料不足檢查
 -> LINE Flex／文字回覆
```

官方健康資料建立索引後，由 PostgreSQL + pgvector 進行向量檢索，並搭配文字檢索與重排。若知識庫不足，系統明確說明限制；需使用網路補充時仍受可信來源與結果評分控制。

### Multimodal Pipeline

```text
文字／圖片／語音／影片／文件
 -> OCR／ASR／Parser
 -> 語言、意圖與主張辨識
 -> RAG 或領域工具
 -> 風險與權限檢查
 -> 文字／台語 TTS 回覆
```

藥袋 OCR 不直接成為最終事實，使用者須先核對候選資訊。台語語音由 Taigi AI Labs STT/TTS 串接；系統可同時處理華語與台語候選，再依文字特徵與相似度選擇。

## 四、可靠性設計

- 來源可追溯：回答卡顯示引用來源。
- 資料不足處理：不自行拼湊藥物安全或健康結論。
- 查核流程：將健康主張正規化後，以檢索證據說明。
- 人工確認：藥袋辨識須核對後才建立資料或提醒。
- 權限控制：跨使用者存取依 GENERAL、SENSITIVE、PRIVATE、PERSONAL 與讀寫動作判斷。
- 評估資產：Repository 已有 RAG、查核、路由、STT、TTS、藥袋與安全規則等評估資料集及報告。

既有台語工程測試中，10 至 150 字的固定測項沒有失敗或逾時；STT 平均 CER 約 0% 至 13.7%，TTS 完整 WAV 回應中位數約 1.55 至 7.86 秒。此結果不代表真實場域或所有口音的辨識率。

## 五、執行計畫

1. 鎖定三條決賽 Demo：台語健康問答、藥袋辨識與用藥、家庭健康照護。
2. 建立真實台語語音與環境噪音測試集，區分辨識、檢索及回答錯誤。
3. 以 Golden QA、來源命中、拒答合理性與人工評分檢驗 RAG。
4. 進行高齡者與照顧者任務測試，確認流程可理解性。
5. 量測 API、運算與維運成本，形成 B2C、B2B2C 或 SaaS 的商用假設。

## 六、預期效益與所需資源

CARE 預期降低高齡者使用健康資訊服務的語言與操作門檻，並讓家庭協作建立在可稽核權限上。系統已具可執行原型，競賽期間希望取得 AI 評估、健康產業場景及商業化導師協助。
